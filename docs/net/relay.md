# Relay Server

The `liero-relay` tool allows two players behind NAT to connect without port forwarding.

## Running the relay

```bash
cargo run --manifest-path openliero-rs/Cargo.toml -p liero-relay
# Listening on TCP  :7777
# Listening on WS   :7778
```

Both TCP and WebSocket listeners start on launch. The native client uses TCP;
the WASM (browser) client uses WebSocket.

## How it works

1. **Host** connects and sends `HOST\n`. The relay generates a random 6-letter room code and replies with `ROOM:ABCDEF\n`.
2. **Joiner** connects and sends `JOIN:ABCDEF\n`. The relay pairs the two connections.
3. Once paired, the relay forwards raw bytes bidirectionally between the two TCP/WS connections. No game logic runs in the relay.
4. If either connection drops, the relay closes the other.

## Room codes

Room codes are 6 uppercase letters (e.g., `XKRMQP`) generated by a 64-bit LCG PRNG
seeded from the current nanosecond timestamp. Codes are single-use; a room is destroyed
when the game ends or either player disconnects.

## Deployment

The relay is a single self-contained binary with no runtime dependencies.
A minimal `systemd` unit:

```ini
[Unit]
Description=OpenLiero relay server
After=network.target

[Service]
ExecStart=/usr/local/bin/liero-relay
Restart=always
User=liero-relay

[Install]
WantedBy=multi-user.target
```

The relay holds no state between games, so it can be restarted at any time.

## Firewall

Open ports `7777` (TCP) and `7778` (TCP/WebSocket) inbound.

!!! note "TLS / WSS"
    The relay speaks plain WS (`ws://`). To serve over `wss://` (required for
    HTTPS-hosted browser builds), put Nginx or Caddy in front and proxy to port
    `7778`.

    ```nginx
    location /liero-relay/ {
        proxy_pass         http://127.0.0.1:7778/;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade $http_upgrade;
        proxy_set_header   Connection "upgrade";
    }
    ```
